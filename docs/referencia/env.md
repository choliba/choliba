# `.env` da pasta de trabalho

> Cada variável do `.env` da pasta de trabalho: onde ficam projetos, agentes, skills e MCPs, qual provider roda os
> agentes e as cores da saída.

Para ver o valor em vigor de cada uma e de onde ele vem (o ambiente, o `.env` ou o padrão), rode
`choliba list config`; as credenciais aparecem só como `definida` ou `não definida`.

Para gravar uma delas no `.env`, rode `choliba set config CHAVE valor`, por exemplo
`choliba set config CHOL_SANDBOX docker`. O comando grava uma chave por vez e diz o valor anterior. Uma chave com uma
lista de valores só aceita um deles. Se o ambiente do processo define a chave, ele vence o `.env`, e o comando avisa.
Uma credencial (`CLAUDE_CODE_OAUTH_TOKEN`, `CURSOR_API_KEY`) não vai na linha de comando, porque ficaria no histórico
do shell. Rode `choliba set config CURSOR_API_KEY` sem o valor: num terminal, o choliba pede o valor sem mostrar o
que é digitado; fora de um terminal, lê do stdin (`echo "$TOKEN" | choliba set config CURSOR_API_KEY`).

Quais destes valores o `agent.yaml` pode usar, e como: veja [Variáveis](agent-yaml.md#variáveis). As credenciais de um
projeto ficam no `.env.json` dele, não aqui: [`.env.json` do projeto](env-json.md).

| Variável                         | Para quê                                                                                                                                                                                                                                                                                                                |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CHOL_GLOBAL_DIR`                | Raiz dos artefatos das execuções e, sem `CHOL_PROJECTS_DIR`, dos projetos (`CHOL_GLOBAL_DIR/projects`). Preenchida pelo `setup` com `.cache/choliba` da pasta de trabalho.                                                                                                                                              |
| `CHOL_PROJECTS_DIR`              | Onde ficam os projetos, se não em `CHOL_GLOBAL_DIR/projects`. Preenchida pelo `setup` com `projects/` da pasta de trabalho.                                                                                                                                                                                             |
| `CHOL_TICKET_RUNS`               | Opcional: raiz de `ticket-runs/`, se não for `CHOL_PROJECTS_DIR`.                                                                                                                                                                                                                                                       |
| `CHOL_AGENTS_DIR`                | Opcional: pasta dos agentes (padrão `.choliba/agents`).                                                                                                                                                                                                                                                                 |
| `CHOL_SKILLS_DIR`                | Opcional: pasta das skills (padrão `.choliba/skills`).                                                                                                                                                                                                                                                                  |
| `CHOL_MCPS_DIR`                  | Opcional: pasta dos MCPs (padrão `.choliba/mcps`).                                                                                                                                                                                                                                                                      |
| `CHOL_AGENTS_PROVIDER`           | Opcional: provider padrão dos agentes (`auto`, `claude`, `claude-ollama` ou `cursor`; padrão `auto`); um `--provider` na linha de comando ganha deste.                                                                                                                                                                  |
| `CHOL_SANDBOX`                   | Opcional: onde o provider roda, `local` (padrão) ou `docker`, num container que só enxerga o que o `agent.yaml` libera (veja [Sandbox](sandbox.md)).                                                                                                                                                                    |
| `CHOL_SANDBOX_IMAGE`             | Opcional: a imagem do `docker` (padrão `choliba-agent`, a que `docker/agent.Dockerfile` constrói).                                                                                                                                                                                                                      |
| `CHOL_NETWORK`                   | Com `CHOL_SANDBOX=docker`, usa `isolated` (padrão, rede bridge) ou `host` (acesso explícito à rede da máquina). No modo `isolated`, o choliba troca `localhost` por `host.docker.internal` nas URLs que entrega ao agente; veja [Rede](sandbox.md#rede).                                                                |
| `CHOL_OLLAMA_URL`                | Opcional: onde o provider `claude-ollama` encontra o Ollama (padrão `http://localhost:11434`); veja [Modelos do Ollama](agent-yaml.md#modelos-do-ollama).                                                                                                                                                               |
| `CLAUDE_CODE_OAUTH_TOKEN`        | Com `CHOL_SANDBOX=docker`: o token de `claude setup-token`, que usa a assinatura do Claude e só faz chamadas ao modelo. `ANTHROPIC_API_KEY` também serve.                                                                                                                                                               |
| `CURSOR_API_KEY`                 | Com `CHOL_SANDBOX=docker`: a chave de usuário do Cursor, gerada em cursor.com/dashboard/api.                                                                                                                                                                                                                            |
| `CHOL_PLAYWRIGHT_MCP_OUTPUT_DIR` | Opcional: onde a ferramenta da run `playwright-cli` grava os arquivos que nomeia sozinho ou que recebem `--filename` relativo (snapshots, screenshots), e onde a `playwright-trace` roda (o trace aberto e os screenshots e anexos que extrai ficam no `.playwright-cli/` dela); padrão `.cache/playwright-cli`.        |
| `CHOL_COLORS`                    | Opcional: cores do choliba, `papel.nome=cor` separados por vírgula (ex.: `agents.test-writer=bright-red`). Papéis: `providers`, `agents`, `states`, `gates`, `labels`. Cores: as 16 do terminal (`red`…`cyan`, `white`, `gray` e `bright-red`…`bright-cyan`). Os padrões estão comentados no `.env` que o `setup` cria. |
